# SwiftFox.shop

Учебный магазин кроссовок на C#, ASP.NET Core Razor Pages (.NET 10) и PostgreSQL. У главной, каталога, карточек товаров, аккаунта, корзины и управления заказами отдельные адреса. Скидки открываются отдельной вкладкой каталога.

## Запуск в Visual Studio

1. Установите PostgreSQL и .NET 10 SDK. В Visual Studio понадобится рабочая нагрузка «ASP.NET и веб-разработка».
2. Создайте пустую базу `shoeshop` в pgAdmin, DBeaver или через `createdb -U postgres shoeshop`.
3. Восстановите демонстрационные данные **одним** из способов ниже.
4. Откройте `SwiftFox.Shop.sln`. В меню проекта **ShoeShop.Web → Manage User Secrets / Управление секретами пользователя** укажите своё имя пользователя и пароль PostgreSQL.

```json
{
  "ConnectionStrings": {
    "ShoeShop": "Host=127.0.0.1;Port=5432;Database=shoeshop;Username=postgres;Password=ВАШ_ПАРОЛЬ"
  }
}
```

5. Запустите профиль **ShoeShop.Web**. Адрес по умолчанию — `http://localhost:5080`. Из терминала можно выполнить `dotnet run --project ShoeShop.Web`.

| Логин | Роль |
| --- | --- |
| `buyer` | Покупатель |
| `manager` | Менеджер |
| `admin` | Администратор |

Авторизация по логину без пароля реализована для учебного сценария. Запускайте приложение локально.

## PostgreSQL

Быстрое восстановление готовой базы в пустую `shoeshop` через клиент psql 17 с актуальными обновлениями. При запуске из корня проекта выполните:

```powershell
psql -X -v ON_ERROR_STOP=1 -U postgres -d shoeshop -f database/swiftfox-demo.sql
```

Или воспроизведите создание схемы и импорт CSV в пустую базу. Даты демонстрационных заказов рассчитываются относительно дня импорта. Этот вариант позволяет в любой месяц увидеть и товары со скидкой, и товары по обычной цене.

```powershell
cd database
psql -X -v ON_ERROR_STOP=1 -U postgres -d shoeshop -f 01_schema.sql
psql -X -v ON_ERROR_STOP=1 -U postgres -d shoeshop -f 02_import_demo.sql
psql -X -v ON_ERROR_STOP=1 -U postgres -d shoeshop -f 03_store.sql
psql -X -v ON_ERROR_STOP=1 -U postgres -d shoeshop -f 04_catalog_expansion.sql
```

Сценарий импорта рассчитан на приложенный набор CSV и выполняется на пустой схеме. В исходном архиве отсутствовали набор `import` и макет ДЭ. Для демонстрации в `database/import/` подготовлены восемь товаров, три аккаунта и история заказов. Скрипт 04_catalog_expansion.sql добавляет 25 моделей с артикулами и вариантами EU 38–44. В полной витрине 33 модели. Остатки, цены, адреса и ФИО в наборе условные.

Чтобы обновить существующую базу с поддержкой размеров, сохраните резервную копию и выполните `04_catalog_expansion.sql`. Скрипт сохраняет существующие карточки, заказы и остатки. Для более ранней базы без таблицы `product_size` сначала выполните `03_store.sql`.

## Предметная область и модель

Покупатель выбирает модель, размер EU и пункт выдачи. Цена позиции фиксируется при оформлении, итог заказа рассчитывается из его позиций. Профиль показывает историю заказов, их статусы и коды выдачи. В каталоге доступны фильтры по бренду, категории и цене. При регистрации создаётся профиль покупателя. Отчество можно указать при регистрации или пропустить. Вход по логину сохраняет учебный сценарий.

В рабочую панель можно перейти из профиля. Менеджер ведёт заказы, просматривает остатки и журнал движения. Администратор также добавляет и редактирует товары, пополняет остатки по размерам, управляет профилями и меняет роли.

Модель товара хранится в `product`. Её варианты и остатки хранятся в `product_size` с составным ключом `(product_id, eu_size)`. Ключ позиции заказа — `(order_id, product_id, eu_size)`. Журнал `inventory_movement` фиксирует изменения остатков с помощью триггера PostgreSQL в той же транзакции. Связи и ключи показаны в `docs/SwiftFox-ER.pdf` и редактируемом `docs/SwiftFox-ER.drawio`.

## Тестовая оплата

На шаге оформления выберите «Банковской картой» и придумайте номер из 13–19 цифр, срок действия в формате ММ/ГГ и код из 3–4 цифр. Браузер проверяет формат и показывает обработку демооплаты. Сервер получает только признак успешной симуляции.

## Бизнес-правила

- Скидка 25% применяется, когда модель отсутствует в заказах предыдущего календарного месяца. В подсчёт входят заказы всех статусов. Цена после скидки округляется до копеек.
- Остатки от 0 до 3 пар отображаются красным. Количество ограничено целыми числами. Ноль в корзине или редактируемой позиции удаляет позицию. В заказе должна остаться хотя бы одна позиция.
- Создание заказа, изменение количества и смена статуса пересчитывают остаток в той же транзакции. При отмене товар возвращается на склад. При восстановлении заказа товар списывается повторно после проверки наличия.
- Для пользователя с заказами удаление отключает вход и переносит профиль в архив. История заказов остаётся связанной с профилем. Профиль без заказов удаляется из базы.
- Количество в корзине хранится в сессии отдельно для каждого размера. Остаток повторно проверяется при оформлении. Повторная отправка уже принятого оформления возвращает тот же номер заказа.
